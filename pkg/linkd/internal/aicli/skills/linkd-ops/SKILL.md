# Linkd 开发调试与运维

使用 `linkd-cli` 连接目标 Console。支持只有远程环境的维护场景；有源码时进一步关联当前实现、测试和文档。不要把旧 KAC 行为或 Linkd 设计草案当作已运行的契约。

## 先发现，再调查

1. 运行 `linkd-cli version`、`linkd-cli config list`，核对用户已经给出的环境、时间窗口、租户和来源/对象身份。执行远程请求始终显式传 `--profile`，不要从默认环境猜测目标。
2. 用 `linkd-cli api list` 和 `linkd-cli api describe <operation>` 获取当前 CLI 的接口、读写属性、参数及分页说明。先查 `server.version` 和 `server.capabilities`；目录存在不代表目标服务已部署该接口。
3. 从最小范围的只读查询开始。已知租户必须传入；缺失必要身份再询问用户，不猜租户。全局调度、基础设施和部分策略索引接口本身可能跨租户，报告时说明范围。
4. 按需阅读 [排障路径](references/diagnostics.md)。以 `event_source_id`、Event/Alert ID、fingerprint、发布版本和时间窗口关联证据。使用小页查询，必要时显式翻页，保留原过滤条件。
5. 输出已确认事实、推断及依据、缺失证据和下一步验证。空结果、HTTP 200、进程 UP 都不单独证明业务正常；保留 `partial/unavailable`、游标失效、截断及刷新延迟的限制。

配置缺失时使用 `config set <profile> --url ... --username ... --password-stdin`。让使用者在本机提供密码，不要求在聊天里粘贴；不要读取或输出原始配置文件。CLI 必须在 PATH 中；未安装时先定位项目使用指南或请使用者安装，不虚构下载地址。

## 操作前的强制最终确认

**即使用户此前已经授权，也必须在最终执行操作前展示完整方案，并获得用户对这份最终方案的明确确认。此前的任务授权、让你“修好它”、已有维护窗口或 CLI 的 `--allow-write` 都不能替代此次确认。**

所有需要 `--allow-write` 的操作（来源创建/更新/删除、告警关闭、审计启动/取消）按以下顺序执行：

1. 完成必要的只读调查，确定实际目标、完整参数及预期效果。对批量请求固定具体对象集合；不得把通配符或“全部异常”当作最终范围。
2. 准备请求文件，使用相同 profile、接口、路径、查询和请求体运行 `--dry-run`。该命令零网络请求，只做本地结构校验；它不验证远端对象存在性、revision、业务配置或权限。
3. 按 [最终操作确认单](references/operations.md) 展示环境与 Console 地址、租户及具体对象/数量、全部最终参数（敏感值脱敏）、变更前后差异、影响、可撤销性、可能的部分生效和验证方式。随后明确询问是否执行，并停止在这里等待回答。
4. **没有用户对本次最终方案的明确确认，不执行操作。** 收到确认后，只对已确认的那份方案添加 `--allow-write` 并执行。确认后环境、参数、文件内容、范围或影响发生变化，必须重新展示并确认。
5. 操作后用只读查询验证实际效果。失败不代表未生效；先核查。再次提交操作也必须向用户确认，告警关闭保持原 `operation_id`、`effective_at`、租户、原因及对象不变。版本冲突不得自动读取新 revision 后覆盖。

不得通过 curl、直接 HTTP、其他工具、源代码脚本或修改保护配置绕过这个流程。不设置永久写入开关。不能因排障任务自行关闭告警、改来源、启动/取消审计或修改后端数据。

`--allow-write` 只解除客户端拦截，CLI 无法验证对话里的人工确认。使用本 skill 的宿主需要允许完成上述确认流程；如宿主限制导致无法取得最终确认，只交付可审阅的 dry-run 方案供用户自行执行，不声称已完成操作。

OneModel 的 `onemodel.close` 仅释放查询快照，不是关闭告警；丰富预览读取已配置资源、计算临时结果，不保存告警、不触发 Hook，这两者可以作为只读诊断使用。若未来接口语义变化，先重新核对实现和目录。

## 开发调试的证据边界

有源码时先看实际代码、测试及当前构建版本，再看 README 和使用文档；领域设计和调研只作假设来源。沿实际调用链定位并给出最小复现、输入条件及文件位置。不要把静态检查、mock 或本地模拟当成真实 Kafka/Redis/MySQL/ES 链路验证。

仅有远程接口时，明确无法从接口证明的内部原因，不臆测日志、数据库记录或部署版本。普通代码修改和本地测试按开发任务授权处理；会影响远程业务的脚本、测试、配置发布或维护动作仍遵守上述最终确认。
