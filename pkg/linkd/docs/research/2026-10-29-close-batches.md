# 筛选关闭批量化与字段收敛验证

日期：2026-10-30。实现快照：`c5e2443a37a1d671e265c758b85a8068c9a539e1`。
本文仅记录实现、合成数据测试方法和脱敏结果，不包含部署位置、环境标识、镜像地址、来源身份或运维记录。
接口见[主动关闭 API](../reference/contracts/alert-close.md)，参数见[配置指南](../guides/configuration.md)。

## 处理方式

原筛选关闭路径循环调用单条关闭，重复读取、连接装配和逐项网络往返限制了吞吐。
现参照合并批次的组织方式，在单请求内自动查询并处理后续块：

- 调用方仅提交关闭条件及稳定操作信息，不指定数量或游标。
- 每块固定 1000 条；只保留 `control_plane.close.concurrency`，默认单请求内部并发 8。
- 不限制不同关闭请求的总并发，不占用普通检索槽，不叠加成员并发配置或固定共享活跃连接硬上限。
- 请求同步预算 20 秒；使用已完成块的平均耗时判断后续块能否启动，预算不足时停止。
- 返回实际逐项结果和 `has_more`。调用方保持条件及原操作信息继续调用，无需管理分页。
- 已启动块仍可能因存储抖动部分生效；失败项保留原操作按 Alert ID 重试的语义，不承诺回滚。

内部依次执行身份批读、租约 pipeline、锁内状态批读、Bulk CAS、索引与缓存 pipeline、
终态清理、流水批写、租约释放、同步 KAC 文档更新。来源发布记录、处理器、Hook 和连接按块复用。
不以并发调用单条 `CloseAlert` 模拟批处理。

## 字段与写入

- 候选只返回 Alert ID；租约准备读取租户、ID、来源、来源版本和 fingerprint 五个身份字段。
- 正常关闭裁决不读取正文、标题或 Enrich，只读取状态、挂起意图和清理、无数据联动需要的事实。
- 原生 CAS 仅替换 12 个状态与派生字段，每项保留已有 `seq_no/primary_term`，不重写正文及丰富数据。
- 终态清理 Journal 批读、Bulk 保存 pending、Redis pipeline 清理、Bulk 保存 completed，复用返回版本。
- KAC 已有文档直接 Bulk 更新 `status/action/source_alarm_status/close_reason/close_time` 五个字段，
  使用 `refresh=false`。仅缺失目标才补读完整 Alert 创建。
- 通用 Kafka V1 Hook 已移除，遗留声明和多余参数忽略。显式启用旧 KAC Kafka Hook 的路径仍可能需要完整快照。
- 同租户同 Alert ID 的投影串行，不重叠的批次可以并行；关闭使用本次保存的不可变终态快照。

## 消除重复投影，保留后续动作

此前同步关闭投影之后仍发布普通变更通知，后台会重读完整 Alert 并再次写入 KAC，随后执行动作。
这项重复读写由代码确认存在，但不能仅凭阶段耗时估算其影响比例。

现将同步成功项分流为动作通知：携带原动作和已写入文档的物理索引位置，后台直接进入既有的刷新、
发送和确认流程，不再读取完整 Alert 或重复更新 KAC。无动作的成功项不发通知。
物理位置仅是队列路由信息，不是水位、摘要、Receipt 或回读确认。

动作队列满时背压后台读取，不丢弃已同步成功的关闭动作；取消时未开始的通知不确认，保留在原有 PEL 恢复。
此背压不阻塞关闭 HTTP 请求。同步失败项继续使用普通通知和原操作重试，不新增补偿任务。

同步接口成功仅确认关闭及 KAC 文档写入被接受，不代表后续动作已经全部执行。

## 诊断与证据边界

原型通过只读对照定位到字段过滤开销。相同 1000 条合成告警、每条正文 4 KiB 的结果：

| `_mget` 返回方式 | 耗时 | 响应字节 |
| --- | ---: | ---: |
| `_source_includes` 选择关闭字段 | 3.02 秒 | 1183548 |
| 完整 `_source` | 0.59 秒 | 5469548 |
| 排除正文、标题及丰富字段 | 0.74 秒 | 1291548 |
| `filter_path` 选择相同字段及版本元数据 | 0.55 秒 | 1155548 |

据此将字段裁剪移到响应编码阶段，保留实时读取和版本条件。这是该样本的定位依据，不能外推所有查询。
另一次 KAC 定位对照中，两种方式均约 0.12–0.14 秒，没有证据支持将其字段过滤认定为主要瓶颈。

原型的投影阶段平均 6.55 秒混入了请求取消，不能视为成功 Bulk 的均值，也不足以归因到 ES。
现分别记录实际查询与窄字段更新 Bulk 的成功、失败、取消耗时，以及可解码响应中的 ES `took`。
对应直方图 count 是该类实际请求数；没有响应的取消不虚构服务端耗时。

## 连续 2 万条合成数据测试

使用 20000 条独立合成 active 告警，每条正文 4 KiB。调用方单路连续重复提交同一关闭条件和原操作信息，
不传数量、游标，不并发 HTTP；服务每块 1000、请求内并发 8、同步预算 20 秒。

| 请求 | 成功关闭 | 耗时 | 结果不确定 | has_more |
| --- | ---: | ---: | ---: | --- |
| 1 | 9000 | 19.467 秒 | 0 | true |
| 2 | 8000 | 15.966 秒 | 0 | true |
| 3 | 3000 | 16.922 秒 | 0 | false |

三次 HTTP 累计 52.356 秒，连续调用墙钟 **52.512 秒**；去重成功身份 **20000**，没有失败或未执行项。
计时不包含数据生成、接入等待和事后核对。全量核对结果：原生 closed 20000、active 0；
KAC 的关闭状态、close 动作字段和源关闭状态匹配 20000 条；关闭流水 20000 条。

该次实验的成功样本：

| 指标 | count | 平均 |
| --- | ---: | ---: |
| 现存文档更新 `projection.bulk.succeeded` | 20 | 3.83966 秒 |
| 更新响应 `projection.es_bulk_took` | 20 | 3.78525 秒 |
| 定位 `projection.locate` | 20 | 0.24173 秒 |
| 实际查询 `projection.search.succeeded` | 21 | 0.22788 秒 |
| 查询响应 `projection.es_search_took` | 21 | 0.20481 秒 |

Bulk count 仅覆盖现存文档的窄字段更新，不包含缺失文档的创建回退。
该次 Bulk 请求时间与 ES 返回 took 接近，但仍不足以说明索引内部为何有该耗时。
本轮同时包含多项优化，不能用总时间差给某一改动分配因果占比。

## 验证及限制

完整 `make check` 已通过，包括格式、普通测试、vet、race、静态分析及 Helm/发布脚本检查。
关键回归覆盖：

- 单请求自动处理 20000 条、内部并发实际达到 8、两个请求名额互不占用。
- 普通检索槽占满时关闭仍可执行；预算不足不取下一块；取消和后续查询失败保留实际结果。
- CAS、缓存、流水、投影部分失败后的稳定操作重试。
- 成功通知不进入普通投影通道，不读完整 Alert、不重复写 KAC；原动作身份、刷新、发送、确认保留。
- 动作队列满后取消，不确认未开始动作；KAC 诊断区分成功、失败、取消及真实 ES took。
- 共享控制客户端没有额外的全局活跃连接硬限制。

合成数据结果不构成一般吞吐承诺。6.5 万条连续关闭、生产负载、复杂 Hook、无数据外部回调及多副本故障恢复
尚未完成同等测试，不能用本轮线性估算替代验收。既有挂起屏蔽/合并意图和外部回调仍按原有领域接口处理。
