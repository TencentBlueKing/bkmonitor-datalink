# 代码审查记录

本目录保存针对特定提交的仓库审查快照。审查记录描述的是**某一时刻**的代码与文档状态，不是现行行为的权威说明，也不是设计决定。

审查记录与其他文档分类的关系：

- 判断当前实现请以代码、测试和 [根 README](../../README.md) 为准；
- 判断设计意图请以 [设计文档](../design/README.md) 和 [功能模块](../modules/README.md) 为准；
- 本目录只回答「在某个 commit 上发现了哪些问题」。

审查中发现的问题被修复或被判定为不成立后，不修改历史审查记录，而是在后续审查中重新评估。审查结论若引出设计变更，应同步更新对应的设计或模块文档，本目录保留发现过程。

每份审查记录至少应包含：

- 审查基线 commit、审查时间和审查范围；
- 实际执行的验证命令及其结果，未执行的检查必须写明阻断原因；
- 按严重程度分级的问题清单，每条给出文件路径、行号和判断依据；
- 明确区分已由代码证据确认的结论与尚未获得运行时证据的推断；
- 审查过程中被排除的误报，避免后续重复排查；
- 未覆盖范围。
