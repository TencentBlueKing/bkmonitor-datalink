# 最终操作确认单

只读准备完成后，实际提交前向用户展示以下内容。已有授权也必须走这一步；不能把本文件的示例当成已批准的操作。

| 项目 | 必须填写的实际信息 |
| --- | --- |
| 环境 | profile、Console 完整基础地址、核实的服务版本 |
| 动作 | 接口名、HTTP 方法，以及操作目的 |
| 范围 | 租户、来源/告警/任务 ID；批量时逐项列明完整集合及数量 |
| 参数 | dry-run 的路径、查询和完整请求体；敏感材料脱敏，操作身份及 revision 保持可核对 |
| 变更 | 修改前后差异，读取证据及其时间；创建/删除也说明具体对象 |
| 影响 | 配置发布、任务调整、状态改变、Hook 或其他外部动作；资源消耗和实际跨租户范围 |
| 失败与回退 | 是否可以撤销、部分生效的可能性、如何核查；未知影响明确写出，不能承诺回滚 |
| 验证 | 执行后调用哪些只读接口、观察哪些状态；刷新延迟如何处理 |

最后明确询问：“是否确认按上述环境、参数、范围和影响执行这次操作？”然后等待。沉默、过往授权、单纯提供参数或自动选中的选项均不是本次最终确认。

无法量化查询成本、外部 Hook 投递或其他影响时，明确写出已知边界和未知部分；缺少判断范围所需的关键证据就继续只读调查，不能把“未知”写成“无影响”。

## 来源管理

通过 `event-sources.get` 取得并核对 revision。`event-sources.apply` 的 `spec` 是完整来源配置，不是任意局部 patch；列出完整 diff。凭据保留遵循服务端当前实现，不主动获取明文秘密，不把脱敏后的整个配置当作任意可覆盖材料。

使用已确认的 `expected_revision`；创建为 0。冲突后停止，读取差异并重新确认方案。成功返回 202 只表示请求已受理，不能据此声称所有 Worker 已使用新发布；继续读取来源发布状态和调度状态。

删除可能停止相应来源的后续处理；说明范围与残留积压，不承诺删除告警历史或回收全部数据。

## 主动关闭告警

最终方案包含 Alert ID、租户、原因、`operation_id`、`effective_at`。可以在准备方案时生成一次 UUID 和明确 UTC 时间，但必须先展示给用户确认；执行或重试不得重新生成。用户确认等待过久导致参数需变化时重新确认。

关闭 active 告警可能执行当前发布来源的 FinalHook。operator_id 由 Console 的认证账号填充，不能在请求体中冒充其他人。该接口不承诺跨多告警事务、失败回滚或外部投递恰好一次。

超时、断连、502 或响应无法解析时，结果可能已生效。先查询告警及流水，再对再次提交说明理由和风险并等待确认；保持全部命令字段不变，不能换一个操作 ID“重试”。

## 策略审计

启动范围由 `event_source_id` 和 `hook_name` 指定，扫描目标中的全部租户；它没有单租户启动参数。审计不修改业务数据，但创建后台任务并消耗存储/Redis 查询预算，因此仍要求最终确认。

取消指定任务也要求最终确认；取消后可能保留不完整结果。查询 latest/get 不需要操作授权。
