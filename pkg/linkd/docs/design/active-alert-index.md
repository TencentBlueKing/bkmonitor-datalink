# 控制面维护活跃告警缓存

状态：2026-10-26 合并扫描并改为分页暂存；运行参数与操作步骤以[使用指南](../guides/active-alert-by-strategy.md)为权威位置。

## 职责与选择

Alert 存储是事实来源。Lifecycle 的策略 Hook 只标记待刷新策略；控制面是正式 Redis 集合的唯一写入者。
采用允许传播延迟的完整快照发布，避免 Hook 与维护者共同 SADD/SREM，以及成员版本、历史 tombstone 和引用计数。
不建立跨 MySQL/ES/Redis 事务，不将索引故障变成告警主流程的失败。

控制面独立任务读取完整已发布来源列表，按非敏感 Redis 实例定位、DB、前缀合并来源，凭据轮换不改变目标身份。
来源停用和 tombstone 不会删除绑定；显式移除 Hook 改变绑定范围。切换或移除整个目标不清理旧前缀。
一个物理 Redis 目标及前缀必须属于一个部署；同一 DB 中多个目标前缀不得嵌套，检测到冲突会停止发布，避免父前缀扫描误删子集合。
不同 DNS 别名不能自动证明是同一实例，运营配置必须保证唯一所有权。

## 刷新与并发

1. Hint Lua 将正式集合 key 加入有上限的待刷新 ZSET，并更新短期 token Hash；重复提示不延后最早执行时间。
2. 控制面先取得整个 Redis 目标的单写入者租约，再领取到期提示；周期校准同时发现 Redis 残留集合。
   有到期提示或周期校准到期时，对该目标绑定来源只建立一次持久化快照，所有租户和策略共用，不再每 16 个策略重扫租户。
3. MySQL 使用单条一致性 SELECT 流式读取；ES 使用一个 PIT 和 `search_after` 分页，默认每页 2000 条。
   每页只读取租户、来源、指纹及恢复有效策略标签所需的字段，提取标签后释放丰富结果。
   ES 不传输 trace、诊断和无关历史 value；补丁覆盖顺序及历史标签语义保持不变。
4. 每页按租户、有效策略分组，写入本轮临时 Set 后释放该页；Redis Set 跨页、跨来源去重。
   进程只累计策略身份、提示 token 和临时集合基数，不保留完整告警或完整成员列表。
5. 整个存储扫描成功后逐策略发布。先比较基数，再用 SSCAN 和 SMISMEMBER 分批比较旧集合与临时集合；无变化不通知。
   提交脚本核对租约、临时集合基数与元数据类型，原子替换正式集合，保存状态，仅确认扫描前领取的相同 token。
6. 内容变化后发布原有两字段通知。空集合通过 UNLINK 删除；非空集合直接 RENAME 覆盖，避免先删后写时的 ACL 局部失败。
   大集合替换的释放延迟受 Redis `lazyfree-lazy-server-del` 配置影响，需要按实际部署测量。

租约覆盖一次完整扫描和发布，取得租约之前不建立快照；未取得租约的控制面本轮不扫描。
失租任务不能发布或释放继任者；操作超时小于租约期限。新旧租约粒度不同的控制面版本不可混跑。
读取失败、取消或后续页不完整时，所有正式集合保留旧状态；单策略暂存或发布失败不影响其他策略在剩余期限内发布。
扫描中新发现的策略可以在本轮建立，但未领取的提示不能被确认；扫描期间的新提示继续保留。
退出时批量清理本轮临时集合，异常退出时由 TTL 回收。

## 周期校准和错误恢复

周期校准把 Redis 已有集合纳入同一次存储扫描，清理数据库已无 active 的残留策略。
数据库中的活跃策略直接在分页扫描中发现并构建，不再“发现后入队再重新读取”。
因此创建提示丢失、关闭提示丢失、进程重启、Redis 丢数据均可重新收敛。

`page_size` 和 `max_bytes` 约束单批投影，不限制总告警数或单策略总成员数。
每行超过字节预算仍失败；多个正常行累计超过预算时拆批继续。ES 原始响应还受仓储响应大小限制。
目标操作保留完整扫描时限、策略数和连接池预算；超时不发布部分结果，普通错误保留旧状态并重试。
Redis 临时集合和正式集合会同时占用服务端内存，容量需覆盖构建期间的两份成员；进程内存随单页及策略数增长。

分组只提取最终 `labels.strategy_id`，保持成功/部分成功 Processor 的顺序覆盖和旧版 value 兼容。
已持久化丰富结果中的无关 Patch 值不再解码或校验；目标标签仍必须是合法标量。
信封损坏、非法目标标签、租户越界或快照不完整均拒绝发布，不能把无法确认解释为空集合。

这是最终一致投影：PIT 不消除 ES refresh 延迟，数据库也可以在查询后继续更新。
不存在跨数据库与 Redis 的线性一致读取保证，Redis 故障期间不保证最新状态或固定恢复期限。
正式集合不设置 TTL，优先保留最后一次成功状态；空 key 与“尚未重建”需通过状态元数据区分。
Lua 原子执行不等于错误回滚，响应丢失或通知失败也不能解释成集合未更新。

## 观测与测试边界

Console 显示成功时间、快照年龄、待刷新标记、策略失败和周期发现失败。Hook 成功率仅度量提示提交。
单元测试覆盖共享来源并集、局部失败保留、没有提示时重建、取消和新提示保留；显式 Redis 集成验证
失租、并发任务、重复发布、元数据损坏、通知和 TTL。MySQL、ES 专项验证窄读取、类型匹配、分页预算和后续页失败。
显式容量集成用例覆盖 20 万条告警、单策略 15 万成员、一次扫描跨租户构建和内容不变时重复刷新。
容量与生产延迟需要根据策略数量、单策略成员数、事件变化率和存储预算另行测量。
