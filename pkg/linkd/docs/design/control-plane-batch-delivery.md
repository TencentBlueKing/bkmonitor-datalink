# 控制面投影批处理与局部更新

本次保持 Lifecycle 记录要求、控制面补扫与投递的现有流程。

## 实现边界

1. 控制面复用已有 Elasticsearch 读写合批器。独立调用在最多 10ms 内聚合为 `_mget` / `_bulk`，保持逐项 CAS、错误与取消语义；队列满直接执行，不增加准入配额。
2. 投影 ACK 只读取身份、业务版本和投影水位，条件更新 `projection` 与 `projection_work`，不复制或回写 Alert 动态业务载荷，不等待 search refresh。归档搬迁与并发业务更新通过重新定位和 CAS 处理。
3. 补扫先检查稳定任务身份；已存在任务不重新构造完整协议快照，也不自动恢复 failed。缺失任务仍实时重读后创建。
4. 投影和动作任务的进度写只替换 `payload.progress` 和 `work`（动作同时维护 `unsettled`），保留首次冻结的请求；状态转换和租户身份在写入边界校验。
5. KAC 写入复用合批器，读取兼容文档只取身份、状态和需要合并的本地字段；状态更新只传送发生变化的映射字段，同一物理索引的已完成写入共享一次刷新。刷新开始后到达的写入进入下一批，不冒充搜索可见。
6. KAC 客户端不再以固定四个 HTTP 名额限制执行器；并发由 `control_plane.delivery` 管理。任务目录与观测接受实际配置的批次大小，单页超过 16 项不再生成假失败。

## 验证要求

覆盖批次部分失败、取消退出、任务 create-only 冲突、既有失败任务不重建、ACK 冲突与归档定位、单调水位、部分更新保留大业务字段及 KAC 本地处置信息、刷新合并的到达边界。运行完整 `make check` 后再发布；部署后核对任务真实完成、积压、CPU 和存储请求变化。
